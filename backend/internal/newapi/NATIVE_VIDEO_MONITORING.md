# 旧原生视频的后台状态跟进

日期：2026-11-21。本批为本地开发验证，不代表已发布或部署。

旧原生视频原来依赖下游继续查询，任务日志才会更新。现在由主站独立装配的 `NativeVideoWorkers` 自动读取上游进度，再写入原生任务历史；它和 New API engine 使用独立上下文、关闭与认领方法，停用一套不会连带取消另一套。既有协议解析、账号并发、代理和仓储继续复用。

## 适用范围

- 本批启用后，经旧原生接口创建的 Grok 生成、编辑、延长，以及 Ark / Seedance 视频。
- 只登记未绑定 JS 插件的普通 API Key 账号，且创建时能够保存原连接摘要。已绑定 Task 插件的账号继续使用既有插件任务队列。
- 更早任务、未记录创建或未保存连接摘要的任务，以及 OAuth / CLIProxy 任务，不猜测回填；继续按原接口查询和处理。
- 本跟进队列只查询状态和更新任务日志。后续阶段已为具有价格快照的新任务加入独立后台结算队列，见 `NATIVE_VIDEO_SETTLEMENT.md`；不提交生成或下载成片，也不把旧任务转成 JS Task。

## 执行与恢复

迁移 `261_native_video_polling.sql` 新增 `sub2api_native_video_polls`。创建历史和登记跟进使用同一条 SQL，任何一项失败都回滚；重复观察不会覆盖连接摘要，也不会为原先未登记的历史补建任务。

| 项目 | 行为 |
| --- | --- |
| 调度 | 每实例 2 个固定 worker，每秒尝试认领到期任务；健康查询后约 15 秒再查，繁忙时可能延后 |
| 多实例 | PostgreSQL `SKIP LOCKED` 认领，2 分钟租约；旧租约不能写入生命周期 |
| 重启 | 未完成记录留在数据库，租约到期后由新 worker 继续 |
| 截止 | 一轮最多 30 秒，查询最多 25 秒并为持久化预留时间；关闭服务取消 I/O，释放并发位 |
| 传输 | 仅 GET，沿用原账号 Key、代理与有效请求头覆写，禁止重定向；只接受 200 / 202 |
| 响应 | 最多 64 KiB，并多读 1 字节检测超限；截断、未知状态及不匹配的任务号不当作成功 |
| 并发 | 复用原账号共享并发位；满载或并发服务不可用时等待，不绕过限制 |
| 重试 | 普通查询错误按 15～240 秒退避；连续 10 次错误转待处理。等待账号容量不消耗错误次数 |
| 总期限 | 最长跟进 24 小时；超过期限转待处理，不把生成任务改失败或免费 |
| 结束 | 生成失败，或生成成功且交付状态明确时结束跟进；已登记自动结算的任务还必须保存最终用量。缺交付或缺用量继续查询 |

数据库中的监控记录仅保存 SHA256 连接摘要、租约、时间、计数和固定错误码，不保存地址、凭据、原始响应或签名 URL。连接摘要涵盖账号、协议、目标 GET 地址、代理及有效请求头策略。相同账号正常轮换 Key 可以继续；地址、代理、请求头、平台、账号类型或插件绑定改变时暂停，避免改用另一套连接查询旧任务。

前台原生查询和后台保存按“历史 → 跟进记录”的顺序加锁，生命周期只能向前推进。前台确认真实终态时，也会关闭已暂停的跟进记录并清除提示。停止账号或连接改变后的待处理不会自行重新启用；后续维护入口已增加管理员恢复查询，需要核查依据、二次验证和相同原连接；不能抢占有效租约。恢复仅查询原任务，详见 `NATIVE_VIDEO_SETTLEMENT.md`。

## 任务日志和费用

列表及详情分别显示生成、交付、计费和后台跟进状态。跟进状态为“后台跟进中 / 后台跟进结束 / 后台跟进待处理”。待处理只说明自动查询需要核查，不会把仍在生成的任务显示为生成失败。详情有固定错误解释和暂停提示。“仅待处理任务”筛选也包含这些记录，并保留用户归属；管理员原有资金操作单独标为“资金对账”。

后台状态更新不等于原生账本完成扣费。后续独立结算队列以最终用量和创建时规则调用原账本；没有成功凭据时金额仍留空，简单模式明确显示未扣费。原接口仍可查询、下载和计费确认，前后台共用首次证据与去重账本，插件资金链路不参与本队列。

本状态跟进批次保存的创建快照仍是计费输入；后续已加入创建时价格和付款来源快照，适用范围与降级边界见 `NATIVE_VIDEO_BILLING_SNAPSHOT.md`。后续已接通符合条件的新任务后台自动结算、最终用量证据及原账本/日志恢复，见 `NATIVE_VIDEO_SETTLEMENT.md`。无完整快照的旧任务仍仅更新状态。

## 验证

使用模拟上游与独立临时 PostgreSQL 验证创建登记的原子性、重复迁移、8 路认领、租约过期与重启恢复、旧租约拒写、前后台锁顺序和并发终态更新。实际启动后台服务、通过本地 HTTP 模拟两种上游，在客户端不查询的情况下记录完成，并确认余额和用量不变。

服务回归覆盖两种协议的进行中/终态/缺交付、未知响应、错误任务号、响应超限/截断、认证错误、并发满载、停用账号、连接改变、Key 轮换、重试上限、取消与关闭。前端验证跟进状态独立于生成及费用状态，中英文文案与类型同步。最终检查结果见本批实施记录；没有发起真实付费生成或操作生产数据库。

本批最终结果：service / handler / repository 聚焦回归共 834 项测试及子测试通过 `-tags unit -race`，包含上述真实数据库与后台 HTTP 场景；前端 2 文件共 11 项界面及国际化测试、Vue 类型检查、受影响文件 ESLint、Vite 生产构建、Go 服务构建与差异检查通过。Wire 已重新生成，生成文件无内容变化。
