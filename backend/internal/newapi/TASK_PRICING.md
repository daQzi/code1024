# Task 多维表达式定价

固定参考 New API `48f9df96ea7c68eae04a0f3687869f232f48929f` 的
`pkg/billingexpr/task_usage_test.go`。使用其 Task 的 `u/tier` 写法和 USD
语义，沿用本站账号、分组与资金账本；不是完整 billingexpr 移植。

## 配置

账号的“视频售价”可以选择“Task 多维表达式”。示例（字段必须由该模型的插件声明）：

```json
{
  "*": {
    "mode": "expression",
    "expression": "tier(\"video\", u(\"seconds\") * (u(\"resolution\") == \"1080p\" ? 0.4 : 0.2) * (u(\"audio\") ? 2 : 1))",
    "service_fee": "0.1",
    "minimum": "0",
    "maximum": "10"
  }
}
```

- `u("字段")` 读取当前模型 `usageSchema` / `usageProfiles` 声明的 number、boolean 或 enum。
  示例中的 `audio`、`resolution` 仅为说明，不能拿去使用未声明这些字段的插件。
- `tier("名称", 金额)` 返回金额并记录所用档位；不再除以百万。
- 允许标量算术、比较、条件、`has/max/min/abs/ceil/floor`，可带 `v1:` 前缀。
- 计算顺序：表达式 USD + 每单服务费，取最低收费，乘分组或用户既有倍率，最后按本站
  8 位金额精度舍入。`maximum` 为倍率前 USD 上限，必须正数。
- 创建时冻结最大额乘客户倍率，不能只冻结估价；否则最终用量跨档时没有已授权的资金。
  账号额度使用其独立倍率冻结，与客户免费分组相互独立。
- 其他固定价、单位成本加价、最终账单模式继续保留；表达式不负责抓取上游价格。

## 保存前与受理前预检

新增或修改的表达式在账号保存前按实际生效模型检查 `usageSchema` / `usageProfiles`，
优先取映射后的上游模型 profile，再回退公开模型。精确模型规则覆盖 `*` 默认规则；完全被
覆盖的默认规则暂不检查 schema。账号无对应模型的新规则会拒绝保存。

预检检查所有字面量 `u` 引用，包括当前条件未走到的分支。按 number 的零、一和单位上限、
boolean 的两值、enum 的组合进行最多 64 次有限采样，拒绝负价、非有限金额及运算错误。
组合太多时先取枚举首尾、截断并保留全末值组合；只检查被引用字段，避免无关 schema
挤占预算。second/count/token/credit 上限分别沿宿主 3600/128/2147483647/2147483647。
这只是提前发现配置问题，**不是证明所有分支安全**；每次实际计价仍检查事实、结果与冻结上限。

时间函数另按确定性的日历边界采样，最多 64 个时刻、各使用首尾两个用量组合，
补查跨日、周日到周六、闰日和年末；不挤占原有 64 个用量组合的预算。

未改动的旧规则可以随账号其他资料编辑保留，但每个新任务在冻结前仍按当前模型 schema
重新预检。存量任务只按原不可变快照结算，不用新增准入规则追溯更改旧合同。

## 最终用量与账务

创建时保存表达式、SHA256、使用到的 schema、用量估计和规格选择器，不保存请求正文、
凭据或未引用用量。之后编辑账号规则或插件元信息，不改变运行中任务的规则。

支持 `hour("Asia/Shanghai")`、`minute("UTC")`、`weekday("Asia/Shanghai")`、
`month("UTC")`、`day("UTC")`。时区必须是字符串字面量，去掉首尾空白；空或无效时区按
UTC，星期日为 0、星期六为 6，月份为 1–12。例：
`u("seconds") * (hour("Asia/Shanghai") < 8 ? 0.1 : 0.2)`。
这些数值全部以**受理时刻**为准，同时保存用到的时区在该时刻的 UTC 偏移；预估、结算和
数据库恢复均使用同一快照，跨天、夏令时或时区数据库升级不会事后改价。
缺少或损坏的时间快照必须转人工核对，禁止回退为结算时的当前时间。

完成时只使用 `_host_final_usage` 中单独保存的实测数字量。外层混合了估计的 `usage`
不得充当最终账单。显式数字零有效；缺少数字、非法 enum/bool 或无效计算转人工对账。
最终没有再次报告的枚举/布尔规格可以取冻结值；明确报告的规格必须校验后使用。
常量表达式无需虚构数字用量。

资金事务锁定任务行，从数据库中的价格与最终事实重新求值，再核对待扣金额；不信任调用方
可修改的内存价格或用量。上限在舍入前检查。账本、解冻、Key/订阅退款、账号额度差额与
结算事件一起提交；幂等重放不重复扣费。结算事件只记录表达式摘要、档位和金额。

确认失败的任务照常全额释放；管理员人工结算仍必须写明依据，且不超过原冻结额。
零客户倍率仍按实际用量释放账号最大额中未使用的部分。

## 明确限制

- 最大 4096 UTF-8 字节、512 AST 节点、128 个缓存编译结果；每次执行有独立 VM 内存预算。
- schema/facts 快照最多 64 KiB，事实仅支持有限标量，不将宿主对象交给表达式。
- 不支持普通 relay 的 token 变量、`fixed()`、请求头/正文探针、动态 `u` 字段名或时区、
  数组、范围、集合迭代、对象成员或任意函数。未开放的语法会明确拒绝。
- 此模式针对持久 JS Task。平台额度耐久投递见 `TASK_QUOTA.md`；原生旧任务、普通文本 relay、
  自动上游询价的完成状态分别见 `HOST_COMPATIBILITY.md` 与 `COMPATIBILITY_BACKLOG.md`。
