# 旧原生视频的缓存丢失恢复

日期：2026-11-21。本阶段为本地开发验证，不代表已发布或部署。

New API 将执行归属和计费上下文保存在任务私有数据中。本项目的插件 Task 已有对应持久快照；本阶段为仍走旧运行时的 Grok / Ark 视频补上必要的恢复信息，沿用现有仓储、账号调度和原生账本。

## 已实现

- Grok 生成、编辑、延长及 Ark 创建成功后，在原生响应写给下游之前，同一条 SQL 同时保存任务归属、生命周期及私有 `pending_billing`。观察写入最多等待 3 秒，不依赖客户端继续连接；写入失败记录错误，不重发已被上游接受的创建。
- 私有快照包含当时的请求模型、计费模型、上游模型、公开别名、分辨率、时长及创建时间，和原 Redis 输入使用同一个规范化函数。没有新增价格计算或资金操作。
- 查询、Grok 下载和 Ark 原生 DELETE 的 Redis 归属读取缺失或报错时，按用户、API Key、有效分组、协议及原任务 ID 查数据库；唯一匹配时继续使用原账号。不会续写 sticky，也不会回退到另一个账号。
- 完成扣费时，Redis 参数缺失、损坏或读取报错，可恢复该账号的私有快照；缺少可靠快照、账号不匹配或数据库不可用时停止本次扣费尝试，不消耗扣费 claim。Grok 不因这些恢复错误默认按 480p 计费；Ark 继续仅使用上游实际报告的 completion tokens。
- 账号归属由数据库恢复时，扣费直接使用同条记录的快照，避免原 Redis 参数键缺少分组/账号维度，在部分缓存丢失或 Key 改分组后读到残留参数；原记录缺快照时也不使用残留参数补造。
- 同号任务匹配多个账号时，数据库恢复返回歧义错误，不任选最新记录。查询有 3 秒上限并遵循客户端取消；有专用组合索引，最多读取两个候选。
- 创建重复观察及后续轮询不能覆盖首次快照。快照不进入公开任务日志、模型详情或下游响应。
- Redis 的共享扣费 claim、失败后的 claim 释放及原数据库 `usage_billing_dedup` / archive 继续防重。数据库恢复不会代替 Redis claim；即使 claim 丢失后再次尝试，持久账本仍防止同一任务重复扣款。

## 升级边界

迁移 `260_native_video_recovery.sql` 添加可空私有列和组合索引，不回填模型/价格、不复制凭据、不改余额或冻结额，也不把旧任务转成插件任务。

| 缓存同时丢失时的已有证据 | 可恢复内容 |
| --- | --- |
| 迁移 258 以前未记录创建，数据库没有任务 | 无法凭任务号补造归属或计费参数 |
| 有原生历史，但创建时未保存私有参数 | 可恢复唯一账号；缺少快照时本次完成扣费保持待确认 |
| 本阶段保存了归属及私有参数 | 可恢复账号及原计费输入，继续原完成扣费流程 |

旧任务的 Redis 数据仍正常时保留原有读取路径。无法恢复并不表示免费：任务日志仍须看到原账本的已提交结算凭据才显示已结算费用，否则显示“原账本待确认”。

本次保存的是计费输入，不是原生售价、连接或凭据的完整快照。旧链路仍使用现有原生定价、账号和认证；仍需保留在途任务的原账号与地址，不能直接把该账号改绑插件或迁移上游。完整的固定价格、固定版本、固定目标及后台结算由插件 Task 链路提供。

本阶段没有新增旧任务后台自动查询、旧任务转 JS Task、OAuth/CLIProxy 的运行时迁移或任意插件原生路由。用户/Key/分组权限、可用账号和原生查询的资金检查继续生效；这不是在整个 Redis 不可用时绕过并发和扣费控制。

后续批次已为有创建时连接摘要的普通 API Key 新任务加入后台状态跟进（迁移 261），见 `NATIVE_VIDEO_MONITORING.md`。仅自动查询状态，不自动结算，也不为本阶段更早的任务补造连接信息；以上缓存恢复与原账本边界仍适用。

再后续批次已为能够可靠解析价格的普通 API Key 新任务增加私有 `financial`，固定创建时价格、倍率、原订阅/余额及额度规则，完成查询/下载复用原账本结算。首次 SQL 价格优先于 Redis；缺价或不支持的规则继续原路径，不猜回填。后台仍不自动扣费，详见 `NATIVE_VIDEO_BILLING_SNAPSHOT.md`。本节上文关于“不是原生售价快照”的描述针对未携带 `financial` 的旧输入。

## 验证范围

使用模拟 HTTP、独立临时 PostgreSQL 和竞态检测验证：四类创建与查询、Grok Range 下载及 CDN 鉴权隔离、响应前落库、缓存清空/读取失败、缺失与错误归属、账号不可用、同号歧义、快照缺失/损坏、截止及取消、快照不可覆盖、升级/重复升级、公开字段隔离、并发和 archive 后重复结算。未调用真实付费模型，也未操作生产数据库。

本阶段最终回归：service / handler / repository 三包共 782 项测试及子测试通过 `-tags unit -race`，包含独立 PostgreSQL 的真实迁移及资金去重；Go 服务生产构建和 `git diff --check` 通过。未变更前端代码，未重跑前端全量测试。
