# 旧原生视频的创建时计费快照

日期：2026-11-21。本批为本地开发验证，不代表已发布或部署。

旧原生视频原来在完成查询或下载时读取当前价格和付款方式。任务生成期间改价、改倍率或切换订阅，可能使旧任务按新设置扣费。本批参考 New API `service/task_polling.go` 的任务私有计费上下文，在现有原生待计费参数中保存创建时规则；完成时仍调用本站原 `UsageBillingRepository`，不另建资金账本。

## 范围与计算

仅对本批启用后、经旧原生入口创建、未绑定 Task 插件的普通 API Key 账号尝试保存。插件任务继续使用原有固定版本、冻结与结算链路。

| 项目 | 固定内容 / 完成时用量 |
| --- | --- |
| Grok 生成、编辑、延长 | 通过现有引擎解析创建时每秒价格；渠道按次配置时保存每次价格。完成时使用原链路规范化后的实际时长；分辨率取创建输入 |
| Ark / Seedance | 保存创建时每个输出 Token 的价格，或现有渠道按次价格。完成时必须有上游实际报告的正数 completion tokens，不由时长估算 |
| 售价与倍率 | 保存单位原价、客户实际单价、输出成本、用户/分组倍率、视频独立倍率或 Token 峰时倍率；计价时刻为创建请求时刻 |
| 付款来源 | 固定原余额或原订阅 ID；完成时切换订阅不会改扣新订阅。原订阅不存在时失败并允许重试，不自动改扣余额 |
| 配额与统计 | 固定创建时 Key 配额、时间窗及账号配额开关、账号倍率和平台；独立账号统计价格和客户售价分别保存 |
| 金额精度 | 私有单价用十进制字符串保存，先乘实际用量再按现有 8 位金额精度量化，避免每 Token 先舍入 |

捕获过程只解析价格，不冻结或扣除资金，也不提交上游请求。它发生在转发创建之前，最多使用 3 秒请求上下文。取消、价格/依赖缺失、Grok Token 定价、Ark 按输出量分档的自定义采购统计规则，以及无法可靠表示为固定单位的规则均不保存本快照；保留原动态完成计费并记录固定告警 `native_video_price_snapshot_unavailable`，不把缺价猜成零价。因此不能把本批描述为全部原生任务均已固定价格。明确配置的零价可以正常保存和结算。

账号统计的 Token 单价按实际输出 Token 计算，即使客户采用按次售价；按次采购统计保持一次，不乘视频秒数或 Token 数。自定义采购统计的分档使用总用量，不能用一个 Token 的价格推算所有档位，本批保留其原路径。

## 持久化与完成扣费

`financial` 放在现有 `pending_billing` 的私有 JSON 中，复用迁移 260 的 8192 字节上限，无新表或迁移。创建成功后绑定准确任务 ID，与任务归属及原始计费输入在响应前一起保存；Redis 保存相同内容。首次 SQL 快照不可被重复创建观察或后续轮询覆盖。

完成查询和 Grok 下载先核对用户、Key、有效分组、原账号、协议及任务 ID，再加载首次 SQL 快照。即使 Redis 中仍有旧版参数，或上游重复任务号导致 Redis 被后来的创建改写，也使用首次持久规则；数据库错误时停止本次扣费，不在该情况下改走动态价格。没有持久记录的升级前 Redis 路径继续兼容；只有 SQL 恢复出的账号不能采用缺少分组/账号维度的残留 Redis 参数。坏身份或坏快照不会消耗扣费 claim。

完成扣费继续使用原 Redis 共享 claim、固定 `grok-video:` 请求身份以及数据库 `usage_billing_dedup` / archive；状态查询和内容下载用同一任务哈希，避免不同 URL/正文触发不同指纹。普通账本事务保证余额/原订阅和 Key/账号额度只更新一次；后续后台结算阶段已将带快照的普通用量日志与原账本扣款放入同一事务；只有匹配账本指纹与完整归属才可补齐旧缺失日志，详见 `NATIVE_VIDEO_SETTLEMENT.md`。失败会释放共享 claim；即使 claim 丢失或归档后再次查询，持久账本仍防重。已带快照的 Ark 用量任务在异步队列满载时同步兜底，不静默丢弃。

简单模式也使用创建时规则：仅记录模式不扣费，仅时间窗模式只记 Key 时间窗。任务日志仍以已提交原账本凭据确认费用；不能把简单模式的日志当成正常资金结算。

快照不含 API Key 值、账号凭据、连接地址、签名 URL 或原始请求正文，不进入公开任务日志及下游响应。已有权限、资金准入、账号可用性检查继续生效；本批不提供余额耗尽后的旧原生查询豁免。

## 后续边界

创建时规则和前台完成扣费的衔接已完成。后续 `NATIVE_VIDEO_SETTLEMENT.md` 已接通有完整价格/连接证据的新任务后台结算、首次实际用量保存、原账本/用量的原子提交与恢复。更早历史、OAuth / CLIProxy 和不支持规则继续原流程，没有回填旧价或把旧任务转换为 JS Task。
