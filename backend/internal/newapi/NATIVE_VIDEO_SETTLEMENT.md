# 旧原生视频的后台自动结算

日期：2026-11-21。本批为本地开发验证，未推送、发布或部署。

以固定 New API `48f9df96ea7c68eae04a0f3687869f232f48929f` 的 `service/task_polling.go`、`service/task_billing.go` 为行为参考：视频在后台推进，创建时保存付款来源，最终用量与生成状态分别处理。实现使用 Sub2API 现有仓储、GenerationService、普通用量表与原账本，保留旧协议；没有直接复制 New API 的资金模型。

## 适用范围

仅新创建、保存了 `pending_billing.financial` 且登记原连接摘要的普通 API Key 原生任务自动登记结算队列。Grok 生成/编辑/延长按实际规范化秒数或一次计费；Ark / Seedance 按实际正整数 `usage.completion_tokens` 或一次计费。规则解析边界沿用 [创建时快照](NATIVE_VIDEO_BILLING_SNAPSHOT.md)。旧历史、OAuth、缺价及不支持规则不猜测回填，继续原流程。插件任务已有冻结/结算链路保持独立。

迁移 `262_native_video_settlement.sql` 增加耐久工作队列和任务日志视图，不添加余额表，不预扣旧原生资金，也不回填价格。创建历史、登记状态跟进和登记结算使用同条 SQL，任意登记失败整体回滚。同步返回终态和实际用量时也可直接进入待结算状态。

## 最终证据和恢复

- 前台查询/下载与后台 GET 使用同一份首次持久最终用量。只保存数量、秒数、输出 Token 和观察时间，最多 1024 字节；不保存正文、签名 URL 或密钥。后来的不同用量不能覆盖首次证据。
- 生成完成和文件可用不代表账单就绪。Ark 缺少有效 Token 时继续查询，15～240 秒退避；连续 10 次缺证据后暂停并显示待处理。不估算 Token，不把缺证据当成免费或生成失败。
- 后台每实例 2 个固定结算 worker，每秒认领到期任务。数据库 `SKIP LOCKED`、2 分钟租约；每轮最多 30 秒，关闭服务取消工作，未确认结果留在数据库等待租约恢复。
- 原生收费继续使用相同 `grok-video:` 账单身份、`usage_billing_dedup` 及其 archive。价格、倍率、原订阅/余额和配额政策取创建快照；读取当前配置不能改变原付款来源。
- 恢复时再次核对用户、Key、分组、账号、协议及上游任务号；格式正确但归属不同的财务快照也不能扣款。坏证据或指纹冲突直接转待对账，临时账本错误重试，最多 10 次。
- 普通余额/订阅/Key/账号额度和 `usage_logs` 在同一数据库事务提交。日志失败回滚整笔扣款。旧进程已扣款但缺日志或留下零金额占位时，只有匹配原账本指纹与完整归属才允许修复日志，不再扣款。
- 结算完成后、队列状态保存前崩溃可安全重放；租约丢失的 worker 不得改写队列。原账单归档后仍然防重。结算命令绕过普通批处理合并，以保留财务和日志的事务边界。
- 简单模式沿用创建规则：仅记录模式原子写用量，不认领财务扣费凭据；仅时间窗模式只更新 Key 时间窗，不扣余额/订阅/Key 总额度或账号额度。明确零价的正常模式仍可显示已结算。

## 控制台和边界

任务日志增加“待结算 / 待对账 / 未扣费”和结算时间线。生成成功但结算待处理时标题为结算问题，不标成生成失败；未知金额留空。失败且没有最终收费证据的自动任务标记未扣费。公开 API 不返回私有用量队列、财务规则、连接摘要或订阅 ID。

已保存的成功原账本凭据及匹配用量才显示已结算；仅生成终态、简单模式用量或队列完成标记均不能替代账本证据。原生内容下载仍使用原接口。

后续维护入口已增加管理员“恢复后台查询 / 重试原账本结算”。需要现有二次验证、至少 4 字符核查依据，且不能抢占有效租约。查询仅恢复原连接的 GET，结算仅重试保存的规则和用量；已完成/失败任务不可重复恢复，坏证据不能强制绕过。状态恢复与私有操作记录同事务，公开时间线仅显示动作及时间，不暴露操作者、核查依据或私有快照。没有新增人工改价、强制扣款或退款。原生非线性价格快照、OAuth、完整 JS Task 化、长期文件保留、耐久平台配额 outbox 仍需后续开发。这一批不等于完整 New API 插件兼容。

## 验证

本地真实临时 PostgreSQL 和本地 HTTP 模拟上游覆盖：原子登记及不回填、首次证据不可覆盖、8 路并发、余额/原订阅、Key/账号额度、日志失败回滚、已扣无日志/零占位修复、归档重放、队列租约恢复、简单模式/零价、无人查询的 Grok/Ark 自动扣费、延迟用量、生成失败、错误归属转待处理和公开数据隔离。服务回归另覆盖缺失/错误/溢出用量、退避、取消、固定 worker 和重复关闭；前端覆盖费用状态和生成状态的独立展示。

未操作生产数据库，未调用真实付费上游。最终检查与数量见实施记录。


## 管理员恢复入口

`PUT /api/v1/admin/task-logs/:task_id/native-maintenance` 接受 `action`（`resume_poll` 或 `retry_settlement`）与 `reason`。接口复用管理员鉴权、Heavy 限流、审计和 StepUp 中间件；普通用户详情不返回操作能力，用户路由不提供此写入口。

迁移 `263_native_video_maintenance.sql` 持久保存任务、管理员、动作、核查依据和时间。恢复与记录同事务；记录失败则不恢复。并发操作按历史→跟进→结算一致顺序加锁，8 路恢复只有一个成功；有效租约返回 409。恢复查询重新给予 24 小时查询期限并清错误计数，仍固定原连接摘要；账号停用或连接改变时拒绝。重试结算不读取当前价格或改付费来源，不能替换任务号、实际用量和金额；已结算再次请求返回 409，不新增扣费。

隔离 PostgreSQL 回归覆盖审计失败回滚、并发恢复、租约拒绝、结算重试完成及重复拒绝；服务回归检查原连接/身份/单位和动作；路由回归确认写入口要求 StepUp；前端检查仅管理员可见、必须填依据和完成后刷新。该入口不提供强制修改坏证据或绕过指纹冲突的能力。
