# 原生视频入口接入统一 Task 执行器

日期：2026-11-21。此阶段完成本地实现与模拟回归，未推送、发布、部署或调用真实付费模型。

以前，插件视频从 `/v1/videos` 进入队列，旧视频接口直接转发。现在，**已经绑定 Task 插件的普通 API Key 账号**也可以接收以下原生请求；它们进入同一个队列、任务日志和账本。

| 下游入口 | 所需插件声明 | 创建响应 | 后续查询 |
| --- | --- | --- | --- |
| `POST /v1/videos` | `openai_video` | OpenAI Video 对象 | `GET /v1/videos/{id}` |
| `POST /v1/videos/generations` | xAI 原生生成 route | `{"request_id":"video_…"}` | `GET /v1/videos/{id}`，处理中 HTTP 202 |
| `POST /v1/videos/edits` | xAI 原生编辑 route，且 route 允许该模型 | 同上 | 同上 |
| `POST /v1/videos/extensions` | xAI 原生延长 route，且 route 允许该模型 | 同上 | 同上 |
| `POST /api/v3/contents/generations/tasks` | Ark 原生创建 route | `{"id":"video_…"}` | `GET /api/v3/contents/generations/tasks/{id}` |

xAI 同时保留现有无 `/v1` 的别名；Ark 保留 `/v3`、`/v1` 及无版本前缀的已有别名。未新增任意插件动态注册 HTTP 路由的能力，也没有开放 `/xai`、`/doubao` 这样的额外前缀。

## 配置与灰度切换

1. 在统一插件中心启用对应的固定版本：`xai` 或 `doubao`，社区脚本需要声明相同的受支持原生 route 和 `openai_video` 模型能力。
2. 在原“账号管理”中添加普通 API Key 账号，填写上游地址、Key、代理、分组及模型映射，并选择插件。地址遵循插件自身的 Base URL 约定，例如原版 `doubao` 使用不带 `/api/v3` 的 API 根地址；不要直接复制旧原生账号的完整端点地址。Grok OAuth / CLIProxy 继续走旧运行时。
3. 明确配置视频售价。支持既有固定售价、人工上游单价加价、分组和用户倍率；Ark 可使用其最终 Token 用量。不会把插件内的模型能力表当作上游报价。
4. 用新账号验证后再逐步切换流量。**旧任务完成前保留原账号和原地址；不要直接覆盖仍有旧任务的原生账号。** 后续已为新观察到的旧原生任务增加数据库归属/计费参数恢复，详见 `NATIVE_VIDEO_RECOVERY.md`；这不迁移旧任务到插件 Task，也不为它们添加后台自动查询。

迁移 `259_native_video_plugin_bindings.sql` 只为已经绑定插件的 API Key 账号补齐原生 route 能力快照，依据它们原来固定的源码版本计算。它不绑定原生账号、不升级源码、不启用停用插件、不修改售价或凭据。修改账号能力后通过现有 scheduler outbox 刷新候选缓存；重复执行不重复产生刷新事件。

## 执行和计费

```text
原生 JSON 请求
  → 原有认证 / 分组 / 入口规则 / 审核
  → 按声明的原生 route 和模型选择插件账号
  → 固定版本 native.decode
  → 固定请求 / 连接 / 配置 / 价格 / 资金来源，原子冻结
  → 返回本站 video_… ID
  → 后台 Task 提交 / 查询 / 终态用量 / 制品声明
  → 持久终态后结算，失败退款，不确定结果待对账
```

- 创建响应表示本地已经接受并持久保存任务，不表示上游已经接受。上游提交由原有有界 worker 执行；创建阶段不再旁路提交一次。
- xAI 的原生生成、编辑和延长分别调用固定版本脚本的原生 decoder，再使用共同的 `buildSubmitRequest`、`parseSubmitResponse`、查询和最终用量 hooks。Ark 原生 `content`、角色、音频和时长参数由 `vendorBody` 保留；模型使用账号映射。
- 任务在重启后从数据库恢复，已经有上游 ID 的任务继续查询。丢失提交结果的任务进入待对账，不自动重发。
- 已接受的任务继续使用原版本、配置、模型映射、目标地址和价格；同账号 Key 可以正常轮换。插件普通停用或账号停调度不重新冻结、不改变已经接受任务的目标地址。
- 原生插件任务只记录到 `sub2api_generation_tasks`，不再额外写旧原生观察日志，也不进入旧 Redis 完成扣费链。
- `Idempotency-Key` 属于当前 API Key；相同操作和相同原始正文重试返回同一任务。换原生操作或改正文返回 409，不能把同一键从生成重放为编辑。此前通过 `/videos/generations` 别名接受的标准 OpenAI 任务仍按原响应格式重放。
- 已冻结任务的重试、查询和内容下载不再要求额外余额；仍检查 Key 状态、用户、分组和任务归属，新请求照常检查资金。

## 返回字段与兼容边界

- 创建和查询返回本站 ID；上游任务 ID、插件 state、任意响应扩展字段、凭据和签名存储 URL 不返回给下游。
- 原生查询使用受限的宿主 DTO，提供标准状态、公开模型、时间、已报告的数值用量和本站鉴权 content 地址。`native.render` 的通用扩展尚未开放，不能把此阶段称为完整原生 route/render 兼容。
- 成片通过 `GET /v1/videos/{id}/content` 下载，继续复用固定 Task 插件的 content 驱动、归属校验、Range 与安全重定向。返回的内容路径是站内路径，下游应相对于本站 Base URL 解析，并携带自己的 API Key。
- xAI 审核拦截和已收费失败保留原生语义：任务可能已收费但没有可下载视频；不得因为没有视频 URL 就退款或展示成免费。已确认的失败仍由统一账本按既有规则处理。
- Ark 自动时长 `-1` 不展示成负数秒数；只返回上游实际报告的数值用量，不把预估 Token 冒充最终用量。
- 不支持 Ark 插件任务 DELETE，返回 405，不伪造取消或提前解冻。原生账号的旧 DELETE 路径保留。
- `callback_url`、原生图片、任意 native route 和 OAuth 执行迁移仍未开放。现有视频入口的草稿/父任务引用已接入严格的原连接固定与私有快照，见 `DERIVED_TASKS.md`；持久文件范围见 `FILE_HOST.md`。
