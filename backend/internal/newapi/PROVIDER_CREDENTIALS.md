# Provider 登录与凭据维护

固定 New API 基线：`48f9df96ea7c68eae04a0f3687869f232f48929f`。以下仅描述本站已经接入的 Provider Chat/Responses 宿主，不能据此认为 Task OAuth 或全部社区插件都已接通。

## 使用路径

1. 安装并启用声明 `login`、且具有受支持文本 relay 的固定插件版本。
2. 在账号里选择这个插件，配置上游地址、分组和具体模型映射。登录插件可以不填静态 Key，先保存账号。
3. 重新打开账号设置，在“插件登录与凭据维护”中开始授权。支持 redirect/paste、fields、device/pending。每个修改操作复用现有管理员二次验证。
4. redirect/paste 完成后，复制回调页显示的完整地址，粘贴回原账号窗口。device/pending 采用明确点击查询，服务端限制最小查询间隔。
5. 凭据保存后，文本 relay、显式模型发现和余额查询共同使用它。查询上游余额不会调整本站钱包、价格或账单。

站点需配置公开前端 URL；生产回调使用 HTTPS。PKCE/state/nonce 由服务端生成。流程绑定发起管理员和登录 session，最长 15 分钟，当前流程每步有 revision CAS。只有发起会话能读取下一步登录信息。回调中存在 state 时必须一致；声明 issuer 时必须匹配；重复参数和上游 error 被拒绝。与固定源码相同，允许省略 state 的上游依赖 PKCE。

前端启动的首个模块先把回调 query/hash 从地址栏清除，再启动路由、账号恢复和应用请求。完整地址只留在内存供一次读取，不写本地存储或自动发送消息。

## 存储和执行约束

- 继续使用原 accounts，不另建“上游连接”。迁移 281 的附属表存放加密凭据、加密登录会话、公开状态、revision 和维护租约。
- 使用现有 `SecretEncryptor`。连接身份只保留平台、类型、代理 ID、固定插件版本，以及地址/Key/配置密文的 SHA256。接口不会接收调用方提供的私有凭据字段。
- 明文凭据只放在 Account 的未导出、不可 JSON 序列化的请求内字段。持久账号、管理 DTO 和调度缓存不会收到解密后的 grant。
- 元数据保存时，如果配置实际没有变化，保留原密文，避免随机加密 nonce 导致登录失效。
- claim/finish 都核对当前账号连接；修改地址、Key、插件版本或配置后，旧刷新结果不能写回。SQL 事务不跨网络请求，数据库租约为 60 秒，单次凭据操作最多 15 秒。
- 相同插件的同一上游账号 ID 不能同时绑定两个有效账号；跨版本也检查，使用数据库事务锁避免两个实例同时存入。
- 静态 Key 仍走原 `checkKey/exchangeKey`，登录凭据走 `credential` data、持久 headers/query 和 `signRequest`；不把两种身份混用。
- 请求提前 30 秒续期；已有其他实例刷新时有界等待其 revision。401/明确拒绝时，全链最多一次续期，且只重试当前步骤。已收到变更请求的流事件时仍禁止重放。
- 与固定基线一致：没有 refresh hook 时不伪造续期；提前续期失败但旧凭据尚未过期，可以继续使用旧凭据；已过期或明确被拒绝时不能回退。`relogin:true` 会停止使用，等管理员重新授权。
- 显式撤销先阻止本站继续调用；远程失败保留 `revoke_pending`，后台重试。登录完成但无法存储时，尽力撤销新 grant；同一账号已在别处登录或读取状态不确定时不自动撤销，以免厂商撤销全部会话。

## 维护

启动两个固定 worker、最多 32 个账号 ID 的队列，共享 32 MiB 后台内存预算。每 15 秒发现到期账号，数据库 `OnlyIfDue` 防止同一批排队 ID 导致重复执行。手动停用账号、暂停调度或停用插件后不会开始新的定时维护。已运行的 hook 必须满足原连接、租约和 revision 才能提交。

- `scheduled` 使用同一份持久凭据；必要时先 refresh。静态 Key 维护先取得 exchange token。
- next、余额和 notify 按原版 typed contract 校验。余额/通知在管理员凭据卡中展示，不写本站资金账户。
- “允许插件自动暂停这个账号”默认关闭，开启后才接受插件的自动暂停请求；后续维护可恢复调用。不会把它变成管理员永久停用。
- hook 失败只存固定错误码，不记录上游报文、密码或 token；15 分钟后再试。worker 停止时会取消并等待在途任务。
- RPC 严格区分未返回 `session/credential` 与显式 JSON null：未返回表示保留，null 表示清空。余额维护不能意外清空凭据。

## 清理、调度与当前边界

账号删除、解除绑定或连接身份变化时，由同事务触发器撤销本地租约并保存原密文授权清理任务；两固定 worker 共享原队列与 32 MiB 预算，只允许通过原版本、地址、配置及未变化的代理执行 revoke。清理失败 15 分钟后重试，10 次失败转人工处理；插件中心“授权清理”显示最近 50 条记录，管理员二次验证后可重新排队。已被其他有效账号使用的上游身份会受保护，不发送撤销请求；清理完成或保护后清除密文。清理租约与登录提交共用身份锁，避免本地绑定与撤销同时提交。

原生请求的认证失败、自定义永久错误和重复流超时停用已通过同事务记录 `reason:disabled` 事件；重复旧响应不重放事件，事件跨重启保留，同账号的 disabled 触发至少间隔一分钟。事件使用固定原因码，不向 JS 传递原始错误。只有账号的自动暂停/恢复开关已开启、且账号自本次自动停用后未被人工修改，`keyStatus:enabled` 才能在保存凭据的同事务恢复账号并通知调度缓存。人工暂停、改配置/名称、换 Key 等均不会被旧维护结果覆盖。

scheduled 的 notify 及插件暂停/恢复通知已接入既有 Ops 告警邮件收件人、严重级别、恢复通知开关和每小时限额配置；插件维护通知独立计数。使用统一的 `ops.alert` 模板、收件人语言和投递记录，邮件正文由模板转义。仅在凭据/原生恢复事务成功之后发送，最多额外等待 5 秒；邮件错误只记录固定诊断，不回滚已保存凭据，不暴露 SMTP 错误或凭据。与固定基线一样采用尽力投递，进程在保存后、发送前退出可能不补发，该通知仍保留在账号凭据卡中。

Task 驱动的凭据生命周期仍需随 R3 接入。当前 Chat/Responses 调度的候选、粘连与最终重查均从数据库批量读取公开状态，提前排除已撤销、待登录、显式自动暂停和不可续期的过期授权；可续期的过期授权在取得并发名额后按原流程续期。调度不解密令牌、不运行 JS，读取失败只排除该批插件账号，不影响原生账号。实际出站前仍再次核对授权。

真实厂商授权仍需在有测试账号和明确测试额度的环境验收。离线测试与模拟上游不等于真实渠道全部可用。
