## 一、已确定的产品要求

1. 以当前 Sub2API 二开项目为宿主，按现有 Go / Vue 风格开发。
2. 对齐固定版本 New API 的完整 JS 插件契约，覆盖任务、Provider 和请求处理三类能力。
3. 上游在现有“账号管理 → 添加账号”中添加，选择插件、填写凭据和配置；不另建重复的上游连接管理页面。
4. 插件管理页负责安装、配置、能力检查、启停、版本升级和回退；一个插件可以服务多个账号。
5. 新绑定插件的 Grok 与 Ark / Seedance 可接共同的任务、计费、文件和监控链路；未绑定的原生账号和旧任务保留 Sub 原执行及查询路径。
6. 先补齐通用插件系统；官转二、官转五等渠道在后续依据统一开发文档作为社区插件交付，不继续以单个渠道决定宿主接口。
7. 对外提供统一 OpenAI Videos 兼容接口；多素材、报价等额外能力作为明确的本站扩展。
8. 支持固定售价、上游成本加价，以及现有分组和用户价格规则。
9. 模型广场按照 New API 的列表组织、主要功能和交互迁移；点击模型进入独立详情页面，不以弹窗代替详情页。
10. 详情页有可直接访问、刷新和分享的地址，包含价格、能力、接口示例和真实监控。
11. 保留当前账号、Key、分组、权限、资金流水、OAuth Transport 插件和已有接口兼容性。

## 二、范围和完成口径

参考 New API 提交固定为 `48f9df96ea7c68eae04a0f3687869f232f48929f`。后续升级单独进行兼容评估。

“完整兼容”按该基线声明的 hooks、utils、配置、文件和宿主语义逐项验收，不能只验证脚本可编译。第三方脚本、自行扩展和未来版本不自动包含。New API 的 Go 内置渠道与 JS 插件分别清点，不能把二者混称为已兼容。

普通图片、音乐等任务能力通过 New API 契约验证；当前批量图片等已有业务的整体迁移不自动加入本轮。文本等现有内置适配保留，并补齐 Provider / 请求处理插件的接入点。

各里程碑均为最终范围的一部分；视频先交付不表示普通 Provider 和请求处理被移出范围。

| 位置 | 职责 |
| --- | --- |
| 账号管理 | 上游地址、凭据、插件绑定、模型映射、分组、并发、优先级和健康状态 |

| 渠道 / 分组定价 | 售价、规格价、成本加价、优惠及最终价格解析 |
| 统一网关 | 下游协议解析、身份鉴权、权限、模型解析、路由及统一输出 |

插件不得直接修改本站余额。插件向宿主返回上游费用和用量事实，由宿主按规则核算。

## 四、最终用户路径

### 4.1 管理员添加上游

```text
插件管理：安装 / 启用插件
             ↓
账号管理：添加账号 → 选择插件接入
             ↓
填写地址和凭据 → 加载 / 配置模型与能力
             ↓
绑定分组、映射、优先级和并发
             ↓
渠道 / 分组：设置售价规则
             ↓
模型广场与 /v1/models 展示有权使用的模型
```

账号表单保留现有认证方式。插件接入方式与 API Key / OAuth 等凭据类型分开建模，不能为了选择插件而破坏既有账号类型和平台调度规则。

### 4.2 用户浏览模型

```text
模型广场列表
   ├─ 搜索、厂商、类型、协议、分组筛选
   ├─ 卡片 / 表格、价格、最近状态与耗时
   └─ 点击模型
          ↓
      独立模型详情页
          ├─ 概览与能力
          ├─ 分组价格 / 规格价格矩阵
          ├─ API 接入示例
          └─ 性能、成功率与历史趋势
```

路由形态在现有前端路由中确定，语义示例：`/model-plaza` 和 `/model-plaza/models/{catalog_id}`。`catalog_id` 是稳定公开标识，详情页展示和复制真实 API 模型 ID。不得直接把带 `/` 的模型名拆成路由层级，也不能用仅前端内存存在的行号作为地址。

依赖：P1、P2。交付：可持久恢复的视频任务闭环。

| 编号 | 任务 | 产物 / 完成标准 |
| --- | --- | --- |
| P3-01 | 建立统一视频请求、结果、状态、用量和文件 DTO / codec | 标准、原生和扩展输入均有明确归一化规则 |
| P3-02 | 新建任务、产物、操作记录和幂等索引 | 保存 owner、账号、插件版本、映射、价格、请求指纹与上游任务号 |
| P3-03 | 分开记录提交、生成、交付与账务状态 | 能表达提交待确认、生成成功但成片未就绪、成片已就绪但账单待定 |
| P3-04 | 实现创建、查询、下载和任务列表核心接口 | 按 P0 选定的 SDK 验证 JSON / multipart、公开 ID 和错误结构 |
| P3-05 | 增加能力、估价、产物列表及必要兼容路径 | 扩展可识别；重混 / 取消 / 删除 / 编辑 / 延长按模型能力开放 |
| P3-06 | 实现持久调度、租约、条件更新、退避和故障恢复 | 多实例只认领一个操作；进程重启后继续推进 |
| P3-07 | 实现上传 / 引用文件 / 上游对象号 / 下载流 | 大文件不经 JS 内存；对象号按上游账号和授权范围隔离 |
| P3-08 | 实现 originTaskIds 和派生任务归属 | 编辑 / 延长任务不能跨用户或错误账号引用上游任务 |
| P3-09 | 实现请求幂等与不确定提交恢复 | 同键同请求返回原任务；同键不同请求 409；不确定提交不换账号重试 |
| P3-10 | 实现有界轮询、超时、终态报告和人工处理入口 | 未知上游状态不伪装运行或免费；操作有审计 |
| P3-11 | 加入上传 / 下载 / URL 素材的访问和资源约束 | 受控地址、重定向凭据隔离、大小 / 时间限制，支持需要的 Range / HEAD |
| P3-12 | 定义任务、产物、文件的保留和清理策略 | 删除展示不提前删除账务依据；有界分页清理 |

关键约束：数据库事务不能覆盖外部 HTTP 提交。对于不支持幂等或查重的上游，超时后无法凭本地租约保证外部只执行一次；必须进入待确认 / 对账流程，不能宣称已实现无条件的 exactly-once。

查询、下载不重新执行“新生成所需余额”检查，但仍执行有效身份、任务归属和访问策略，不绕过禁用 Key 等既有安全边界。

## 七、必须通过的重点验收场景

| 类别 | 场景 | 预期结果 |
| --- | --- | --- |
| 幂等 | 同一请求并发重发 / 同键不同内容 | 返回同一任务 / 明确 409，不重复提交 |
| 不确定提交 | 上游接收后本地超时 | 待确认，按原账号核对，不自动跨渠道再生成 |
| 持久恢复 | 冻结后、提交后、结算前后杀进程 | 恢复后资金与任务一致，不重复扣退 |
| 多副本 | 多个 worker 同时认领与终态更新 | 操作、终态、结算与指标防重 |
| 客户端退出 | 提交后关闭网页或不再查询 | 后台仍能完成任务跟进和结算 |
| 价格 | 未知、零、过期、最终高于冻结额 | 按明确策略处理，不把未知变免费 |
| 官转五 | 上传重试、慢估价、分镜先完成、账单延迟 | 不重复上传 / 生成，不把分镜当完整交付，不提前成本结算 |
| 版本 | 运行中升级 / 停用插件、改映射和倍率 | 旧任务保持原契约与价格，阻止新请求不误杀存量维护 |
| 权限 | 跨用户任务 / 隐藏分组 / 文件地址 | 访问被正确拒绝，公开缓存不串权限 |
| 规格 | 不同分辨率、时长、参考素材 | 不静默截断或降档，价格和指标条件正确 |
| 监控 | 一次任务查询多次、无样本、内部重试 | 一次任务只计一次，样本与尝试可区分，无样本不造数 |
| 广场 | 点击、分享、刷新、登录切换和返回 | 独立详情页正常，链接稳定，权限和个人价格正确 |
| 回归 | 旧 OAuth 插件、Grok / Ark 原生接口和历史任务 | 继续按已有约定工作 |
| 资源 | 大文件、恶意响应、脚本超时、队列满、取消和关闭 | 返回明确错误，释放内存 / 文件 / 连接 / worker，账务不丢失 |

## 八、实施时的项目约束

- 先核对 GitHub 固定源码及已有实现，依照本项目分层、仓储、Ent、Wire、Vue、i18n 和测试风格开发。
- 遵守 `docs/agent-resource-safety.md`，使用共享 ingress 内存预算、有界 worker / 队列 / 缓存、I/O 截止和受控关闭。
- 后台执行不持有 `*gin.Context`、响应 writer 或可变请求对象；创建不可变任务 / 账务快照。
- 新协议通过 RelayKit / 共享 codec；文件二进制由宿主流式读写，JS 仅使用引用。
- 新迁移号实施时分配，避免当前分支变化造成冲突；账务使用持久事务与已有精度策略。
- 普通日志、指标、公开接口不输出 Token、AK/SK、服务账号私钥或采购明细。
- 对受影响代码运行必要测试和构建；资源、并发与恢复改动运行相应 race 检查，不因纯文档规划运行全量业务测试。
- 不用“插件能编译”“接口健康”代替真实任务、计费和权限验收。

## 九、工期与外部依赖的管理
